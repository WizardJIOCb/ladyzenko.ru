# Записи лекций

Обновление 17 ноября 2026: папка Google Drive содержит 14 MP4, суммарно 14 983 774 777 байт. Подтверждены 13 лекций «Школы отцов»; найденная первая запись длится 1 ч 16 мин. Файл без названия опубликован как «Дополнительная лекция Людмилы Ладыженко», без предположений о теме. Каждая запись стоит 1000 ₽, доступ на 30 дней. Восемь старых товаров сохраняются в админке, но скрыты из публичного каталога до подключения соответствующих записей.

Для просмотра требуется личная ссылка заказа и подтверждение почты покупки восьмизначным одноразовым кодом. Код действует 10 минут, ограничены частота отправки и попытки. В базе хранится только проверочный код. Новый вход завершает предыдущий сеанс покупателя. Плеер получает отдельное краткосрочное разрешение, продлевает его каждые 15 секунд; другой плеер требует явного переключения. На видео поверх изображения выводятся почта и часть номера заказа. Срок покупки и возвраты проверяются сервером перед выдачей медиазапроса. Cookie сеанса закрыт от JavaScript и передаётся только по HTTPS в рабочем окружении.

Это практическое ограничение передачи доступа, а не DRM: технически опытный пользователь сможет сохранить уже получаемый поток или убрать водяной знак браузера; запись экрана тоже не исключена. Полные вставки и ссылки «Школы отцов» удаляются из публично отдаваемых страниц нового сайта. Доступ к исходной папке Google Drive и прежним приватным записям RuTube должен отдельно закрыть их владелец; см. TILDA-YOOKASSA.md. Снимки исходного контента в Git не являются закрытым хранилищем.

## Хранение и доступ

На сервере `dubai` записи импортируются в `/var/lib/new-ladyzenko-recordings` (0750 root:nginx, MP4 0640). `ops/import-recordings.py` принимает приватный JSON-манифест `{id,url,duration}[]`, скачивает MP4 до 720p, проверяет наличие видео/аудио и длительность через ffprobe. Запись получает файл `*.verified.json` только после проверки. Манифест хранится вне веб-каталога, 0600. URL и токены не выводятся в журнал.

`ops/configure-remote-media.py source|consumer` получает `{secret}` через stdin, на веб-сервере также можно передать `relayPort:38444`. На видеосервере `/commerce-source/` требует закрытый межсерверный заголовок; на веб-сервере `/commerce-remote/` — `internal`, проксирует только безопасные имена MP4. Приватные Nginx include имеют права 0600. Не выводить их содержимое. Резервные копии находятся в `/var/backups/new-ladyzenko-remote-media/`.

Прямое соединение оказалось слишком медленным для видео: 4 МБ могли загружаться около двух минут. Рабочая доставка идёт через `ladyzenko-media.service`, loopback `127.0.0.1:38444`. `ops/media-relay.py` параллельно получает до 16 диапазонов по 256 КиБ и выдаёт их строго по порядку; размер, ETag и Content-Range каждой части сверяются, буфер ограничен окном. Межсерверный HTTPS проверяет системные CA. Исходящий адрес задаётся приватным параметром `bindAddress`. Значение `0.0.0.0` позволяет системе выбрать адрес по действующему маршруту; правила VPN и маршруты сам сервис не меняет. Проверка 4 МБ через полный Nginx-тракт заняла около 10 секунд. Сам файл остаётся на видеосервере, дисковый кеш на веб-сервере не создаётся.

Сервис работает с DynamicUser, получает только `{secret,bindAddress}` через systemd LoadCredential из `/var/lib/new-ladyzenko-commerce/media-source.json` (0600). Ключи ЮKassa и SMTP ему не доступны. Код устанавливается в `/opt/new-ladyzenko-media-relay/media-relay.py`, unit — `ops/ladyzenko-media.service`. При ротации межсерверного секрета синхронно обновить источник, приватный конфиг доставки и credential, затем перезапустить `ladyzenko-media`. Сервис слушает только loopback и дополнительно проверяет межсерверный секрет даже на локальном запросе; доступ посетителя к записи по-прежнему проверяет API заказа до внутренней переадресации Nginx.

После проверки файла и доставки его имя добавляется в `lectureRemoteFiles` приватного `/var/lib/new-ladyzenko-commerce/config.json`, например `"school-lecture-02":"school-lecture-02.mp4"`. Настройка содержит только имена, не URL или секрет. Исходные восемь товаров остаются выключенными до точного сопоставления с файлами.

Покупатель оплачивает выбранную запись через ЮKassa. Подтверждённый рабочий платёж открывает видео на странице заказа и ставит письмо с личной ссылкой в очередь. Тестовый платёж, чужой заказ, истёкший срок или полный возврат не дают доступа. Браузер не получает ссылку на RuTube или межсерверный секрет. Прямые приватные URL возвращают 404. Ограничение применяется к копиям на новом сайте; старые страницы Tilda и приватные ссылки RuTube остаются под управлением их владельцев и здесь не отзываются. Запись экрана или уже скачанную копию отозвать невозможно.

## Проверки

`node --import tsx --test tests/*.test.ts`, `npm run build`. HTTP-тест проверяет владение заказом, неподтверждённый платёж, 30-дневный срок, возврат, тестовый режим и безопасный внутренний маршрут удалённого видео. Перед включением каждого товара требуется проверить его MP4, закрытый источник и Range-доставку через веб-сервер.

`python3 -m unittest discover -s tests -p 'test_media_relay.py' -v` проверяет полную выдачу и диапазоны через HTTP, порядок частей при параллельном завершении, суффикс/HEAD/416, закрытые пути, локальную аутентификацию и отбрасывание усечённого ответа источника. Сервис `ladyzenko-media` должен быть active; его журнал не содержит URL с секретами. При неисправности сначала закрыть новые покупки записей и восстановить доставку. После первых покупок курса нельзя откатывать каталог на версию, в которой отсутствуют ID проданных лекций: они нужны для просмотра существующих заказов и писем.

Для прямой сборки MP4 без перекодирования: `ops/import-recordings.py <private-manifest> <private-media-directory> --direct`. Частный список воспроизведения создаётся с правами 0600, URL не попадает в аргументы FFmpeg или журнал. `ops/verify-recordings.py` проверяет H.264/AAC, декодирует начало/середину/конец и выдаёт отчёт с контрольными суммами трёх диапазонов файла. Передать его через stdin в `ops/activate-recordings.py` на веб-сервере: скрипт проверит те же диапазоны через закрытый HTTPS-прокси, прямые 404, сохранит предыдущий конфиг и включит только проверенные записи. Существующие заказы и реквизиты не переписываются.

### Проверка доставки 22.11.2026

После изменения маршрута до видеосервера трафик шёл через `tailscale0`, а привязка к публичному исходящему IP приводила к ConnectTimeout и ответу релея 502. Приватный `media-source.json` сохранён в резервной копии; изменён только `bindAddress` на `0.0.0.0`, сервис перезапущен. Проверены защищённый диапазон 0–1023 (206, ровно 1024 байта) и воспроизведение первой полной записи в браузере администратора. Проверка TLS, межсерверный секрет, loopback и авторизация посетителя сохранены. Общая причина предшествовавших перебоев HTTPS/SSH не установлена; старое сообщение OOM в консоли не подтверждалось журналом за последние два часа.

Прямой публичный канал между узлами затем снова перестал устанавливать TCP-соединения. Проверен альтернативный HTTPS-канал до `video.ladyzenko.ru` через внутренний адрес Tailscale видеосервера: 206 и 1024 байта, с проверкой имени сертификата и межсерверного ключа. Для одного `ladyzenko-media.service` создан drop-in `source-route.conf`: `BindReadOnlyPaths=/var/lib/new-ladyzenko-commerce/media-source-hosts:/etc/hosts`. Файл содержит копию hosts и адрес видеосервера Tailscale для этого имени. Системный `/etc/hosts`, VPN, DNS и правила firewall не изменены. После рестарта релей снова проверен: 206 и 1024 байта. Для отката убрать только этот drop-in, выполнить daemon-reload и перезапустить релей; при необходимости восстановить прежний приватный media-source.json из резервной копии. Общий сбой публичного HTTPS/SSH этим изменением не устранён.
