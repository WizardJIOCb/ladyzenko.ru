# Оплата на new.ladyzenko.ru

## Состояние и настройки

Сервер: SSH alias `myserver`. Сайт работает через существующий `new.ladyzenko.ru.service`, Nginx проксирует запросы на loopback `127.0.0.1:3007`. Релизы размещаются в `/var/www/new.ladyzenko.ru-releases/<commit>`, активный — симлинк `/var/www/new.ladyzenko.ru-current`. Первоначальный каталог `/var/www/new.ladyzenko.ru` сохраняется для отката.

В `/var/lib/new-ladyzenko-commerce/config.json` (0600, каталог 0710, группа www-data имеет только право прохода к приватному видео) находятся настройки магазина и SMTP. Формат — `ops/config.example.json`. Секреты и SQLite не входят в Git. Процесс работает с UMask=0077. Покупки, возвраты и очередь писем находятся в `orders.sqlite` в этом же приватном каталоге. Файл `signing-key` нужно сохранять вместе с базой: он нужен для личных ссылок и cookie заказов. При смене ключа старые личные ссылки перестанут работать.

`enabled`, `legalApproved` и `fiscalizationConfirmed` по умолчанию выключены. При отсутствии любого обязательного параметра покупки блокируются на сервере. Продажу лекции также блокирует отсутствие её приватного MP4. Цены услуг: 2000 / 4000 / 6000 ₽. Цены лекций извлекаются из Tilda по стабильным идентификаторам; `scripts/sync_products.py` останавливается, если число товаров неожиданно изменилось.

## Перед включением оплаты

1. Дождаться одобрения магазина ЮKassa именно для new.ladyzenko.ru. Получить ShopID и ключ на вкладке этого магазина; тестовый и боевой магазины имеют разные реквизиты. Вставить ключ через SSH в приватный `config.json`; не передавать его в чат, Git или клиентский JavaScript.
2. Утвердить страницы `/payment-info`, `/offer`, `/privacy`, статус продавца и схему чеков. Пока `legalApproved=false`, страницы помечены проектом и оплата выключена.
3. Настроить чек с продавцом/бухгалтером. Если API должен передавать чек, добавить `receipt: { "vat_code": <подтверждённый код>, "tax_system_code": <при необходимости> }`. Если чек формируется другим способом, не добавлять `receipt`, но подтвердить работоспособность всей схемы. Только после проверки установить `fiscalizationConfirmed=true`. Для консультаций при передаче чека в API используется `full_prepayment`; последующее оформление зачёта предоплаты после встречи остаётся обязанностью продавца. Для записей используется `full_payment`.
4. В ЮKassa установить HTTP-уведомления `https://new.ladyzenko.ru/api/commerce/webhook`: `payment.succeeded`, `payment.canceled`, `payment.waiting_for_capture`, `refund.succeeded`. Уведомление не принимается на веру: сервер получает объект заново через аутентифицированный API и сверяет сумму, валюту, магазин, режим и номер заказа.
5. Проверить SMTP до запуска. Сервис `commerce-worker.timer` раз в минуту сверяет ожидающие платежи и отправляет письма из сохраняемой очереди. Возврат браузера не подтверждает оплату. Доступ по тестовому платежу к настоящим материалам не открывается.
6. Пройти sandbox-сценарий и отдельно согласованный платёж в рабочем магазине. Проверить оплату, чек, страницу заказа, письмо, отмену и возврат. После этого `mode=live`, `enabled=true`. Не переключать магазин/ключ при наличии несверенных заказов: перед этим закончить сверку, сохранить архив базы и оставить прежние реквизиты доступными для старых операций.

Изменения `config.json` подхватываются без сборки. Записывать JSON атомарно через временный файл в том же приватном каталоге, затем `mv`, с правами 0600.

## Как подключить запись позже

Положить MP4 в `/var/lib/new-ladyzenko-commerce/media/` с именем из латинских букв, цифр, `_` и `-`. В `lectureFiles` сопоставить ID из `lib/lecture-products.json` с этим именем, например `"lecture-1798546824600": "tristan.mp4"`. Проверить, что файл относится к нужной лекции и не доступен по старой публичной ссылке. Только после этого появится возможность купить запись. Включение записи в новом магазине не меняет права и каталог video.ladyzenko.ru.

Nginx отдаёт MP4 только через `internal` location `/commerce-private/` после проверки заказа. Прямой URL — 404. Срок — 30 суток с подтверждённой оплаты; после полного возврата просмотр запрещён. Скачанную ранее копию или запись экрана отозвать невозможно. Текущее серверное ограничение применяется при новом запросе к файлу; уже полученный браузером буфер не отзывается.

## Операционные проверки

`node --import tsx --test tests/commerce.test.ts`, `npm run build`.

`systemctl status new.ladyzenko.ru commerce-worker.timer`, `journalctl -u commerce-worker.service`. Не выводить `config.json`, API Authorization, cookie или личные ссылки в публичные логи. В журнале Nginx нет ключа личной ссылки: он передаётся во фрагменте URL, затем удаляется из адресной строки и меняется на HttpOnly cookie.

Номер заказа сам по себе не даёт доступа к заказу. При неоднозначной ошибке API повторяется тот же запрос с тем же ключом идемпотентности и тем же телом в течение 23 часов; позже нужна ручная сверка. Возвратов сайт сам не инициирует. Возвраты оформляет уполномоченный пользователь в кабинете ЮKassa; webhook полного возврата закрывает доступ.

## Откат

В `/var/backups/new-ladyzenko/<timestamp>` сохраняются прежняя конфигурация Nginx, unit-файл, прежний drop-in (если был) и путь предыдущего релиза. Сначала выключить приём новых платежей в приватном конфиге. Для предыдущего релиза вернуть симлинк `new.ladyzenko.ru-current`, перезапустить сайт и проверить HTTPS. Для первоначальной версии удалить только созданный drop-in `commerce.conf`, восстановить Nginx из конкретной резервной копии, выполнить `systemctl daemon-reload`, `nginx -t`, перезапуск сайта и reload Nginx. Базу заказов, SMTP, signing-key и платёжный worker не удалять: они нужны для сверки и поддержки уже созданных заказов.
