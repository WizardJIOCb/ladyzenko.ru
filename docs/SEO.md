# SEO и подготовка переезда

Технические исправления от 17 ноября 2026 года сохраняют временный домен закрытым. Смена DNS в эту работу не входит. Публичный контент откроется для индексации после подтверждённого переключения конфигурации на `https://ladyzenko.ru`.

## Что работает

На страницах зеркала обновляются title, description, canonical, Open Graph и связанный граф WebSite/WebPage/Person/BlogPosting. Текст статьи и дата публикации сохранены. Автор, профиль и публикация видны читателю; содержательная правка через CMS показывает «Обновлено» и меняет dateModified. Сохранение без изменений не меняет дату. Карточки записей имеют индивидуальные метаданные, автора и Product; цена и наличие Offer публикуются только при доступной покупке. Названия, биография и ссылки взяты из существующих материалов. Непроверенные награды, звания и отзывы не добавлены.

`new.*` получает noindex в HTML и X-Robots-Tag. Временный sitemap пустой, чтобы не предлагать закрытые URL для индексации. После переключения origin на основной домен карта содержит публичные канонические страницы, разделы и карточки записей. /new, старые страницы покупки и приватные маршруты исключены. lastmod берётся только из сохранённой даты изменения; для страниц без достоверной даты не выдумывается. Публичные загружаемые CMS-изображения разрешены robots.txt.

На основном домене зеркало индексируется. Старый new.* перенаправляет публичные GET/HEAD на тот же путь основного адреса кодом 308. Личные заказы, checkout, админка, API и webhooks сохраняют старый хост, чтобы не потерять cookie доступа и оплату. Они остаются закрытыми от поиска. www требует отдельной проверки DNS и сертификата; сейчас не подготовлен.

## Аналитика и цели

Используется один счётчик Метрики `106094504`; старый `101283816` из зеркала удалён. Счётчик загружается только после «Разрешить». Отказ сохраняется; изменить его можно кнопкой «Настройки аналитики». Вебвизор, карта кликов, автоматическое отслеживание ссылок и хеша отключены. URL и referrer очищаются от query/hash; из utm_source сохраняется только короткий разрешённый список источников. Заказы и админка не подключают счётчик. Покупательские данные не передаются.

Идентификаторы целевых событий для настройки в кабинете Метрики:

- `purchase_click` — переход к покупке;
- `checkout_view` — открытие формы оплаты;
- `checkout_created` — сервер принял создание заказа, перед переходом к провайдеру;
- `subscription_success` — сервер сохранил форму подписки;
- `contact_telegram`, `contact_email`, `contact_phone` — нажатие соответствующего контакта.

Настройка целей в кабинете и факт поступления данных в владельческий отчёт требуют доступа к Метрике. Проверка вызова JS API не равна проверке кабинета. «Успешная оплата» не выводится из клика или return_url: её подтверждает существующий серверный процесс ЮKassa. Количество живых заказов и подтверждённых оплат включается в приватный серверный отчёт, без персональных полей. Письма/платежи в процессе проверки не создаются.

## Серверные журналы и проверка

Оба хоста используют отдельный `/var/log/nginx/ladyzenko-site.access.jsonl`, с hostname, безопасным путём, статусом, методом, User-Agent, источником и referrer hostname. Query, hash, cookie, тело формы и личные пути не записываются в этот журнал. IP остаётся в закрытом серверном журнале; отчёт сохраняет только агрегаты. Ежедневная оценка браузеров использует IP и User-Agent с солью дня и не является точным числом людей. User-Agent бота не подтверждён его IP. Тесты с Codex/Ladyzenko-Health и geo_audit исключаются.

Установщик: `python3 ops/install-seo.py`. Он сохраняет настройки сайта, создаёт отдельный формат и ротацию журналов, приватный ключ IndexNow, исходную очередь публичных страниц и таймеры. Не меняет платёжные реквизиты, пароли, DNS или контент CMS.

`ladyzenko-seo-health.timer` выполняет проверки каждый день в 07:10 по Екатеринбургу. Результаты — `/var/lib/new-ladyzenko-commerce/seo/latest.json` и `seo/reports/YYYY-MM-DD.json`. Проверяется доступность, canonical, schema и ожидаемый режим индексации на главной, статье и записи; учитываются доступные серверные агрегаты. Ошибки дают неуспешный статус systemd и запись в журнале. Внешние уведомления и подключения Search Console/Вебмастера не настроены; эти источники явно помечены недоступными. Снижение трафика не объявляется по нескольким новым дням без базы.

`ladyzenko-seo-indexnow.timer` проверяет очередь раз в пять минут. На new.* он ничего не отправляет. После переезда проверяет DNS, доступность и индексируемость главной и файл подтверждения. Ключ находится в `seo/indexnow-key`, публичное подтверждение — `/indexnow-key.txt`, как требуется протоколом. Ключ не печатать в отчётах. Публикация/восстановление CMS и смена доступности записи пополняют очередь. Неуспешная отправка повторяется с задержкой, принятые элементы удаляются с учётом параллельных изменений. Ответ 200 означает получение, 202 — ожидание проверки ключа; индексация не гарантирована.

Ручная проверка без изменения данных: `python3 ops/seo-health.py --summary`. Для повторного обхода всех URL использовать сохранённый исходный список, поскольку staging sitemap намеренно пуст.

## Проверка переключения

`ops/prepare-domain.py --install` обновляет ранее установленный сценарий ожидания DNS. Он ждёт A=82.146.42.213 без AAAA у 1.1.1.1 и 8.8.8.8, выпускает TLS, проверяет сайт и меняет origin. Дополнительно проверяет canonical и индексируемость главной на основном хосте и редирект с временного. При ошибке возвращает предыдущие origin и конфигурацию Nginx. Владелец меняет DNS позже; делать это самостоятельно не нужно.

После реального переезда повторно проверить статьи, записи, robots, sitemap, TLS, публичные редиректы, старые ссылки на заказы и webhook. Панели Вебмастера и Search Console обновляются в кабинете после подтверждения прав. Подключения панелей и публикации на внешних площадках без доступа не имитировать.

## База и журнал гипотез

База технического аудита 17 ноября: 136 sitemap URL, 114 с noindex, 22 карточки без canonical; 61 sitemap URL без description; автор был указан у 4 из 85 статей. Владельческие показатели показов, позиций и обращений нейросетей недоступны. Логи до выделения домена не дают надёжной полной базы именно этого сайта. Старую базу не подменять нулём.

| Гипотеза | Изменение | Проверка | Откат |
|---|---|---|---|
| H1: устранить технические противоречия перед переездом | Общие правила индексации, тематические метаданные, авторство | Все исходные URL: 200, один robots, заполненные title/description/canonical, H1, валидный граф. На staging всё noindex, на основном публичное index | Возврат предыдущего релиза при недоступности, потере контента или нарушении защиты записей |
| H2: получить сопоставимую базу обращений | Отдельный журнал, один добровольный счётчик, цели | Через 14 полных дней после запуска проверить полноту журналов и сравнить одинаковые дни недель; раздельно учитывать переезд и кампании | Отключение внешнего счётчика при утечке приватных URL; серверный журнал сохраняется |
| H3: ускорить обнаружение редакторских изменений | Очередь IndexNow после смены домена | Проверить приём и реальные даты обнаружения в Вебмастере. Ответ API не считать индексацией | Приостановить timer при ошибочных/приватных URL или ограничении частоты |

Контентные гипотезы пока не запускались: сначала нужны спрос/выдача, выбор нескольких приоритетных тем и согласование с автором. Заголовки-вопросы и короткие ответы добавлять там, где это улучшает материал, без массовой переписи авторских заметок. Кросспосты: сначала выбрать площадку аудитории, сверить оригинал и ссылку, затем оценивать отдельный канал. llms.txt и сводные баллы не являются обязательным исправлением.
